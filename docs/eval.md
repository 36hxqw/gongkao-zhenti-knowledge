# 评测：考点标注质量 + 检索可用性

本文件说明 `tests/eval.py` 的评测口径、两档评测集的来源与局限、阈值取值依据，以及
人工扩充 gold 的流程。核心原则：**评测集要么可 100% 判定，要么明确标注为弱标注、不设门槛**。

```
python tests/eval.py            # 默认：强标注集卡阈值，弱标注集仅展示
```

## 1. 为什么是两档评测集

题目的 `module` / `code` 是否标对，需要一个「标准答案」。本库没有人工逐题标注的预算，
只能利用原卷自带的结构信息。实践中发现两类证据的可靠性差别极大：

| 证据 | 例子 | 可靠性 | 用途 |
|---|---|---|---|
| 题干自带的题型标志词 | 「……填入问号处」「根据上述定义，下列属于」「A 对于 B 相当于 C 对于 D」 | 高：标志词是题型的定义特征 | **强标注集**，参与 CI 阈值 |
| 抽取阶段的 `sub`（原卷小节标题） | `sub=图形推理` | 低：标题会「粘」到后续同节所有题 | 弱标注集，仅作对照 |

因此评测集拆成两档：`tests/gold.jsonl`（强标注，默认）与 `tests/gold_weak.jsonl`（弱标注，仅展示）。

## 2. 强标注集 `tests/gold.jsonl`

### 2.1 来源与规则

只收「题干自带题型标志词」的题，标志词与考点的对应关系如下（实现在 `tests/eval.py`
的 `STRONG_RULES`，纯规则、不读取题库已有分类，避免自我循环）：

| 题干标志词 | 模块 | 考点 |
|---|---|---|
| 填入问号处 / 呈现一定规律 / 分为两类…图形 / 从所给的四个选项中 | 判断推理 | `PD-TX` |
| 根据上述定义 / 按照定义，下列属于（符合、不属于） | 判断推理 | `PD-DY` |
| …对于…相当于… | 判断推理 | `PD-LB` |
| 如果…那么 / 只有…才 / 除非…否则，且设问落在「推出 / 结论 / 可知 / 以下哪项」 | 判断推理 | `PD-LJ` |
| 依次填入横线 + 选项为词语（选项最长 ≤ 12 字） | 言语理解 | `YY-LJTK` |
| 「这段文字 / 文段 / 作者」+ 主要 / 意在 / 主旨…，且设问在题干尾部 | 言语理解 | `YY-ZXJL` |
| 重新排列 / 语序 / 排列组合最连贯 | 言语理解 | `YY-YJPX` |
| 题干是纯数字或分数数列（≥3 个数且有括号） | 数量关系 | `SL-SZ` |
| 与原文相符 / 不符、符合文意 | 言语理解 | `YY-XJPD` |
| 最适合做（作为）标题 | 言语理解 | `YY-BTTR` |
| 接下来最可能… / 下文最可能… | 言语理解 | `YY-XWTD` |

约束：

- **一条题命中多个不同考点视为歧义，直接丢弃**（当前无此情况）。
- 只收 `canonical == id` 的主记录，重复变体不计分，也保证 `search.py --id` 一定能取到。
- 每条记录的 `evidence` 写明命中的标志词，便于复核。

### 2.2 抽样与构成

- 分层格：`(prov, decade, 模块)`，每格最多 **8** 条，格内按考点轮转取，保证小类不被淹没。
- 固定随机种子 `20240101`，遍历顺序全部排序后再抽，**同样的数据重复重建得到逐字节相同的文件**。
- 当前规模 **189 条**，覆盖 3 个模块、11 个考点：

  | 考点 | 条数 | 考点 | 条数 |
  |---|---:|---|---:|
  | `SL-SZ` | 45 | `PD-DY` | 12 |
  | `PD-LJ` | 26 | `YY-XJPD` | 9 |
  | `PD-TX` | 21 | `YY-YJPX` | 8 |
  | `YY-LJTK` | 19 | `YY-XWTD` | 7 |
  | `YY-ZXJL` | 16 | `YY-BTTR` | 13 |
  | `PD-LB` | 13 | | |

- 分层构成（prov × decade）：国考 24 / 20 / 16，广东 24 / 24 / 24，湖北 21 / 20 / 16（2000s / 2010s / 2020s）。

> 关于「每个 (prov, decade) 最多 8 条、总数 150–220」的取舍：只有 3 省 × 3 个十年 = 9 个格子，
> 每格 8 条上限最多 72 条，与 150–220 条无法同时成立。因此把分层格细化为
> `(prov, decade, 模块)`，每格上限 8 条、每省每个十年约 20 条，总量 189 条。

### 2.3 局限

1. **只覆盖 11 个考点**：资料分析 9 个考点、常识判断 8 个考点没有可靠标志词，
   `PD-KX`（科学推理）、`YY-YJTR`、`YY-PZYD` 等也没有纳入，考点准确率不代表这些考点。
2. **标志词法是「高精度、有漏」**：只收能把话说死的题，所以样本偏向长题干、规范设问；
   题干只有「A B C D」的图形题、纯选项式类比题不会进入强标注集。
3. **模块准确率会暴露题库自身的章节切分问题**：少数题的题干类型与所在章节不一致
   （如广东 2009 统一卷若干言语题被切到数量关系章节），金标按题干判定，因此扣分。
   这类扣分是**题库缺陷**，不是分类器缺陷。
4. 189 条样本下，1 条错误约等于 0.53 个百分点，阈值需留出余量（见第 5 节）。

## 3. 弱标注集 `tests/gold_weak.jsonl`（仅展示，不设阈值）

### 3.1 来源

从仓库上级的 `pipeline/out/xingce_raw.jsonl` 取 `sub`（原卷小节标题）与 `sec`（章节标题），
仅当 `sub` 能唯一映射到一个考点时才作为样本；`sec` 只给模块级标注：

| `sub` / `sec` | 模块 | 考点 |
|---|---|---|
| 图形推理 / 定义判断 / 类比推理 / 逻辑判断（演绎推理）/ 科学推理 | 判断推理 | `PD-TX` / `PD-DY` / `PD-LB` / `PD-LJ` / `PD-KX` |
| 逻辑填空（选词填空）/ 片段阅读（阅读理解）/ 语句表达 / 篇章阅读 | 言语理解 | `YY-LJTK` / `YY-ZXJL` / `YY-YJPX` / `YY-PZYD` |
| 数字推理 | 数量关系 | `SL-SZ` |
| 数学运算 | 数量关系 | `null`（只评模块） |
| `sec` 含资料分析 / 常识判断 | 资料分析 / 常识判断 | `null`（只评模块） |

抽样同强标注集（`(prov, decade, 模块)` 每格 5 条、种子 `20240101`），当前 **190 条**
（含考点 91 条 / 仅模块 99 条）。

### 3.2 噪声实测：`sub` 是「章节级」而非「逐题级」

`sub` 的语义是「最近一次出现的小节标题」，一个标题会粘到其后的同节所有题上。证据：

- 国考 2016 副省级第 76–115 题（判断推理 40 题）**全部** `sub=图形推理`：
  其中 76–85 是图形推理，86–95 是定义判断（「……是指……」），96–105 是类比推理
  （「佩刀:刀鞘」），106–115 是逻辑判断（「……由此可以推出」）。
- 国考 2000 统一卷第 71 题题干是「计算机的普及……由此可以推出」，也标成 `sub=图形推理`。
- 广东 2004 统一卷第 31 题是病句题（「下列没有语病的一句是」），因上文小节是
  「语句表达」而被标成 `YY-YJPX`。
- 71 个「判断推理」章节中，有 **52 个**整节只出现一个小节标题（1951 题），说明标题没有逐题更新。

因此弱标注集的考点准确率（当前 **36.3%**）**主要反映标签噪声，不能用来判断分类器好坏**；
它的模块准确率（当前 **99.5%**）仍有参考价值，因为 `sec` 是章节级信息、且题库的 `module`
本就由 `sec` 派生。弱标注集保留的价值是：记录「原卷结构证据」的覆盖率，以及观察题库
标注与原卷结构的系统性偏离方向。

## 4. 指标定义

在强标注集上（弱标注集同口径，但不卡阈值）：

| 指标 | 定义 |
|---|---|
| module 准确率 | 全部样本中 `data/xingce.jsonl` 的 `module` 与 `gold_module` 一致的比例 |
| code 准确率 | `gold_code` 非 null 的子集上，`code` 与 `gold_code` 一致的比例 |
| 混淆矩阵 | 错配对「金标 -> 预测」，模块、考点各列前 10 |
| 按模块分组 | 每个 `gold_module` 的样本数、模块准确率、考点准确率 |
| `--id` 取题率 | 随机 50 条，`scripts/search.py --id <id>` 退出码 0 且输出含 `[id]` 的比例（期望 100%） |
| `--kw` 命中率 | 随机 20 条，取题干前 12 个字（去空白）做 `--kw`，目标出现在前 10 条的比例 |

检索两项为**可用性观测**，不设硬阈值。当前实测：`--id` 50/50 = 100%，`--kw` 18/20 = 90%。
两项 `--kw` 未命中的原因分别是：① 题干是整节共用的指令（「把下面的六个图形分为两类」），
同串命中过多、目标排不进前 10；② 评测口径去掉了空白，而 `search.py` 是字面子串匹配、
正文仍保留 OCR 空格，未做空白归一化会误判。后者建议在检索侧做空白归一化（本次未改 `scripts/`）。

## 5. 阈值与当前实测

| 指标 | 实测（189 条） | 阈值 | 说明 |
|---|---:|---:|---|
| module | **96.8%**（183/189） | **90%** | 原定 95%；按「实测 − 5pp 再向下取整到 5%」取 90%，给题库演进留余量 |
| code | **92.6%**（175/189） | **80%** | 高于默认值，保留 80% |

任一不达标时 `tests/eval.py` 退出码 1，并列出失败样本 id（最多 10 个，`--verbose` 全量）。
**阈值用于防回归，不代表绝对水平**：样本量小、且题库标注本身在演进，阈值取在实测值下方留约 5pp 余量，
避免因 1–2 条样本抖动导致 CI 常红。可用 `--min-module` / `--min-code` 临时覆盖。

当前最常见的偏差（强标注集）：

1. `YY-ZXJL` -> `SL-OT`（3 次）：言语题被切到数量关系章节（4 条同类，均为广东 2009 统一卷）。
2. `PD-DY` -> `PD-LJ`、`PD-LJ` -> `PD-DY`（各 2 次）：判断推理内部考点误判。
3. `SL-SZ` -> `SL-OT`（2 次）：数字推理落入「数量关系·其他」。

## 6. 本地运行

```bash
# 默认口径（强标注集卡阈值 + 弱标注集展示）
python tests/eval.py

# 看全部错例 / 临时放宽阈值
python tests/eval.py --verbose
python tests/eval.py --min-code 0.85

# 重建两个评测集（需要 data/xingce.jsonl；弱标注集还需要上级 pipeline/out/xingce_raw.jsonl）
python tests/eval.py --rebuild-gold
python tests/eval.py --rebuild-gold --raw ../../pipeline/out/xingce_raw.jsonl
```

纯标准库、不联网、不修改 `data/`。Windows 控制台若为 GBK，脚本会自动把 ✅/❌ 降级为
`[OK]`/`[FAIL]`，中文输出不受影响。

CI：`.github/workflows/ci.yml`，ubuntu-latest + Python 3.11，
依次运行 `scripts/selfcheck.py`、`tests/test_skill.py`、`tests/test_tools.py`（存在才跑）、
`tests/eval.py`，并设置 `PYTHONIOENCODING=utf-8`。

## 7. 扩充 gold：人工标注流程

### 7.1 先补哪些

按优先级补强标注集未覆盖的部分：

1. 资料分析 9 个考点（`ZL-BASE` … `ZL-COMP`）——题量最大、目前**完全没有** code 级样本；
2. 常识判断 8 个考点（`CS-ZZ` … `CS-SH`）——同上；
3. 低频但易错的 `PD-KX`、`YY-YJTR`、`YY-PZYD`、`SL-RC`、`SL-RY`、`SL-JT`、`SL-NCC`，
   以及当前没有强标注样本的 `PD-SJ`（事件排序）、`SL-OT`（其他数量关系）；
4. 强标注集已经覆盖的考点，按省份/年份补齐（每个 `(prov, decade, 考点)` 建议 5–8 条）。

### 7.2 标注什么

每条一行 JSON，字段与 `tests/gold.jsonl` 完全一致：

```json
{"id": "GK-2024-fs-X101", "gold_module": "资料分析", "gold_code": "ZL-BILI", "evidence": "原卷第101题设问问比重"}
```

要求：

- `id` 必须存在于 `data/xingce.jsonl`，且是 `canonical == id` 的主记录（重复变体不计分）；
- `gold_module` 取 6 个模块之一：资料分析 / 数量关系 / 言语理解 / 判断推理 / 常识判断 / 申论；
- `gold_code` 必须能在 `docs/kaodian-taxonomy.md` 中查到，且其模块与 `gold_module` 一致；
- `evidence` 写清判定依据（原卷题号 + 页码 / 小节标题 / 标志词），便于复核与争议仲裁。

### 7.3 写到哪里

写入 `tests/gold_manual.jsonl`（可选文件，一行一条，UTF-8，**不要加注释行**）。
`tests/eval.py` 会自动合并：同 `id` 覆盖规则样本，其余追加；重建 `gold.jsonl` 不会冲掉人工样本。
**不要把人工样本直接写进 `tests/gold.jsonl`**，它会被 `--rebuild-gold` 覆盖。

### 7.4 怎么评审

1. 标注者对照原卷 PDF（`国考2000-2026真题pdf/`、`广东公务员考试真题pdf版/`、
   `湖北公务员考试真题pdf版/`）；`references/juan/*.md` 是生成稿，仅作检索辅助，不作最终依据。
2. 另一位评审者**盲标**同一批（至少抽 10%，且不少于 20 条），两人一致率 ≥ 95% 才入库；
   不一致的题按 `docs/kaodian-taxonomy.md` 的口径仲裁，并把口径写回本文件。
3. 入库后运行 `python tests/eval.py --verbose`，确认新增样本的错例可解释；
   若强标注集指标变化超过 2pp，在本文件第 8 节记录原因。
4. 人工样本累计 ≥ 30 条时，重新评估第 5 节阈值（仍按「实测 − 5pp」定）。

### 7.5 扩充强规则（可选）

若某考点的标志词是题型的定义特征，可在 `tests/eval.py` 的 `STRONG_RULES` 增加一条规则，
然后 `--rebuild-gold`，并人工抽查该规则命中样本 10 条以上确认无误；否则请走 7.3 的人工标注。
